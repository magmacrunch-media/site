hypnopompia

the iOS shell for magmacrunch arcade games

The shared parts that turn a magmacrunch web game into an App Store app: the app itself, Game Center leaderboards and achievements, and the tools for testing and for the store listing. None of any game's rules are in here; each game keeps its own.

the technical version

Everything an App Store build of a magmacrunch game needs that has nothing to do with the game: the Capacitor and Xcode project, a native Game Center plugin, the pipeline that turns a web page into an app bundle, and the tooling for the store and for testers. magma-kit does the same job for the desktop apps.

It runs no game logic. A game’s rules live in that game’s repo, once per platform. Every piece here started inside george boole’s port and moved out once a second game needed the same thing, so anything only one app needs stays in that app.

what's here

native/ The Game Center plugin and view controller, Swift, copied byte for byte into each game’s app
pipeline/ The bundle transforms every build shares, and a sweep that fails on anything the app would have to fetch
sync.mjs Copies native/ into a game; --check compares hashes across every game that uses it
fastlane/ Shared lanes for App Store Connect: turn on Game Center, upload the listing, send a build to TestFlight. Each is a dry run until confirmed
check-metadata.mjs A game’s store copy against App Store Connect’s field limits, before an upload rejects it
check-game-center.mjs Leaderboard and achievement ids and their art, before any of them are created
deploy-sim.mjs Puts each app’s Simulator build on a private page for testers with a Mac
tests/ 84 checks on node’s own test runner, and both ends of the copy check run in CI

the shared transforms

The changes every web game needs before it can ship as an app, done the same way for all of them: making it run with no internet connection, opening outside links in the browser, and fitting the screen around the notch.

loadShims Injects the app-only shims after the score bootstrap, so a shim is listening before the game can dispatch anything
pointSharedAssets Repoints shared assets at the bundle, which has no parent directory to climb to
stripStamps Drops the cache-buster stamps, which a bundle that ships its own files has no use for
viewportNotch Adds viewport-fit=cover so the viewport reaches the notch
outboundLinks Opens outbound links in the system browser, rather than navigating the app into a dead end with no back button
the sweep Fails the build on anything the bundle would have to fetch over the network to render

keeping the copies in step

Every game gets an exact copy of the app code kept here. A check compares the copies, so if one is edited by mistake the build fails, instead of the games quietly drifting apart.

the technical version

The Swift in native/ is byte-identical in every game, so a hash comparison is a complete drift check. It runs from both ends: each game’s CI checks its own copy, and this repo’s CI checks every game listed in consumers.json. Edit it here, never in a game, then copy it out. Node 22 or newer, and nothing else:

node tools/sync.mjs ../../games/<game>
node tools/sync.mjs --check
node tools/check-metadata.mjs ../../games/<game>/ios
node tools/check-game-center.mjs ../../games/<game>/ios

the name

After Hypnopompia by Texas Hold’Em Lava Dome, from Pompous Fanfare for All Occasions (2019). Adenosine is the molecule that builds sleep pressure; hypnopompia is surfacing out of it.
