magmacrunch

the terminal arcade, and the Python engine its cabinets run on

v0.14.0 PolyForm Noncommercial Python 3.10+ 16 cabinets

An arcade that runs in a terminal window. Type one command and choose from a menu of games drawn in text characters. Each game is its own package, and installing one adds it to the menu.

the technical version

A terminal arcade by magmacrunch media: one command, a menu of every cabinet installed on the machine, and the Python engine those cabinets run on. The arcade and each cabinet are pure-Python wheels on PyPI, with nothing to compile anywhere.

how games join the arcade

The games aren't built into the arcade. Each one is a separate package: install it and it appears in the menu, uninstall it and it's gone, and the arcade itself never needs a new release for a new game.

the technical version

Games are not bundled into the arcade. Each one lives in its own repository beside its browser and Wii versions, publishes its own wheel, and declares one line:

[project.entry-points."magmacrunch.games"]
george-boole = "boole.arcade:GAME"

The launcher enumerates that group at startup, so installing a game adds it to the menu and uninstalling removes it, with no new release of the arcade. Nothing in the launcher imports a game, so it runs with none installed and says how to get one. A game that fails to load is reported by magmacrunch --list rather than silently skipped.

the object it points at

Anything with an info and a start(host). Both halves are structural protocols, so a game qualifies by having the members, not by inheriting anything.

GameInfowhat the menu reads before seating it
key, title, blurbthe entry point name, the card's title, and one line under it
fpsframes per second the game wants; a turn-based game says so too
hold_mshow long a keypress counts as held, since terminals report presses and never releases. 0 is one key, one action
min_cols, min_rowsthe smallest terminal it draws in; below that its card greys out and says the size
score_keythe scoreboard name, when it is not the key: a board shared with the browser build
accentthe colour the cabinet is known by, brought by the game rather than kept in the launcher
lower_is_betterfor games whose record is the smallest number: moves, seconds
Hostwhat a game may ask of whatever runs it
renderer, inputthe character-cell surface to draw on, and the session's input
push_scene, pop_scenea scene stack; popping the last one hands control back to the menu
seatedwhether the game was placed over a launcher, so it can show the way back
quitend the session and release the terminal

The same game runs alone as its own command, owning the terminal, or seated in the arcade, where the launcher owns it. Nothing in the game changes between the two.

in the engine

character-cell renderera cell buffer, a camera, and Textual and Rich as the only dependencies
scene stack and loopa fixed-step game loop with a scheduler, and scenes that push and pop
input that knows terminalsheld keys inferred from auto-repeat, or one key, one action, chosen per game
a UI kitbig pixel text, menus, dialogue, a HUD, glyphs and themes
high scores that lasta file per game, written atomically, shaped like the web arcade's scoreboard
colour optionalNO_COLOR is honoured, and nothing is readable only in colour

It came out of texastoast's terminal backend, with no tkinter and no GUI.

about

A terminal arcade by magmacrunch media: one command, a menu of every cabinet installed, and a way into one. It needs Python 3.10 and a terminal of at least 36x17; the cabinets ask for more, around 59x22.

Run it without installing anything with uvx magmacrunch, or see the terminal arcade page for pipx, pip and Homebrew.
